SHT31（温湿度センサー）メイン

SHT31 の中温度と湿度を測り、センサーの中で 0〜65535 の数字に変換デジタル 16ビット
I2C（線4本）ラズパイが「測って」と命令し、数字を受け取る電源・信号とも 3.3V
ラズパイ数字を ℃・% に計算し、壊れていないか確認（CRC）5秒ごと
記録補正を足して、1分ごとにSDカードへ。警報の判定もここ1分ごと

つなぎ方

  • センサー：Adafruit SHT31-D（基板の上に SHT31 が載ったもの）
  • ラズパイのピン → ブレッドボード → SHT31-D の4本（線の色は今の配線）
    • 緑：1番ピン（3.3V）→ ブレッドボードの ＋ の列 → SHT31-D の VIN
    • 茶：6番ピン（GND）→ ブレッドボードの － の列 → SHT31-D の GND
    • 紫：3番ピン（GPIO2 = SDA、データ）→ SHT31-D の SDA
    • 青：5番ピン（GPIO3 = SCL、時計の合図）→ SHT31-D の SCL
  • 電源：ラズパイの 3.3V（SHT31-D は 2.5〜5.5V で動く）
  • ADDR ピンを VIN につないで、I2C の番号（アドレス）を 0x45 にしている

数字の計算（データシートの式）

温度[℃] = -45 + 175 × 温度の数字 ÷ 65535 湿度[%] = 100 × 湿度の数字 ÷ 65535
  • 例：温度の数字が 26214 なら -45 + 175 × 26214 ÷ 65535 = 25.0℃
  • 測るたびに「高精度・1回測定」の命令を送る。読み間違いは CRC（検査用の数字）で見つけて捨てる
  • 管理欄の「補正」の数を足してから記録・判定する（例：-0.5 なら 0.5℃ 下げる）
  • SDカードの記録は、その1分の区切りで測った値（平均ではない）

Pt100（白金測温抵抗体）比較用

Pt100白金の線。温度で抵抗が変わる0℃で100Ω、1℃で約0.385Ω増える
Y2Kb Pt100 モジュール小さい一定の電流を流して電圧を測り、抵抗 → 温度に変換温度の文字にして送る
USBUSBシリアル（CH341）で文字を送る10秒ごと・921600bps
ラズパイ「現在,平均,最大,最小」の行から現在の温度を取り出し、補正を足して記録1分ごと

つなぎ方

  • Pt100 の線 → Y2Kb の Pt100 温度測定モジュール（Y2KB-046）→ USB ケーブル → ラズパイ
  • モジュールは Pt100 の2線式・3線式・4線式のどれでもつなげる。USB のほかに RS-485（Modbus）・Grove（I2C）でも読める
  • モジュールの電源は USB から（5V）
  • 差し込み口：ラズパイの hcd.0 側（最初から差していた方）。K型熱電対と逆に差すと名前が入れ替わる
  • USB ケーブルはデータ通信できるものが必要（充電専用だとランプは点くが認識されない）

数字の考え方

抵抗[Ω] ≒ 100 × (1 + 0.00385 × 温度[℃]) （JIS / IEC の Pt100） 例：25℃ → 約109.6Ω、0℃ → 100Ω
  • 温度への変換はモジュールの中で行い、ラズパイは送られてきた温度の文字をそのまま使う
  • -50〜200℃ を外れた値は、断線などの疑いとして記録しない

K型熱電対比較用

K型熱電対2種類の金属（クロメル・アルメル）の先端の温度差で電圧が出る1℃の差で約0.041mV
Y2Kb K型熱電対モジュールごく小さい電圧を測り、つなぎ目側の温度（冷接点）を足して温度に変換温度の文字にして送る
USBPt100 と同じ形で文字を送る10秒ごと・921600bps
ラズパイPt100 と同じプログラムを「ktc」の名前で動かして記録1分ごと

つなぎ方

  • K型熱電対 → Y2Kb の K型熱電対モジュール → USB ケーブル → ラズパイ
  • モジュールの電源は USB から（5V）
  • 差し込み口：ラズパイの hcd.1 側（あとから差した方）

数字の考え方

出る電圧 ≒ 0.041mV × (先端の温度 − つなぎ目の温度) 例：先端 25℃・つなぎ目 20℃ → 約0.2mV。モジュールがつなぎ目の温度を測って足し、先端の温度を出す
  • 電圧がとても小さいので、線を長くしたり、ノイズの多い電線の近くを通したりすると値がふらつきやすい
  • -200〜1300℃ を外れた値は、断線などの疑いとして記録しない
  • 指で先端をつまむとすぐ温度が上がる（どちらのモジュールか確かめるときに使える）

THD-R-C（4〜20mA 温湿度センサー）比較用

THD-R-C温度・湿度を電流で出す（2本）4〜20mA
150Ω の抵抗電流を電圧に変える0.6〜3.0V
RPi-GP40T電圧を 0〜4095 の数字に変える（1目盛り 1.25mV）SPI でラズパイへ
ラズパイ電圧 → 電流 → ℃・% に計算し、補正を足して記録5秒ごと（記録は1分ごと）

つなぎ方

  • 温度：THD-R-C の A → GP40T の A0。A0 と G0 のあいだに 150Ω
  • 湿度：THD-R-C の B → GP40T の A1。A1 と G1 のあいだに 150Ω
  • G0・G1 は THD-R-C の電源の −（GND）へ
  • THD-R-C の電源：DC 24V。ACアダプター（bitstrong BS-ACDC-2420。入力 AC100〜240V、出力 DC24.0V 2.0A（48W）、PSE マーク付き、プラグ 外径5.5mm・内径2.1mm、極性はセンタープラス＝プラグの中心が＋）→ パワーコネクター（2芯の電源用コネクター。プラグを＋と－の線に分ける）→ THD-R-C の電源の＋・－。この 24V はラズパイの電源（CPI-RAS）と共用している（電源と時計）
  • 4〜20mA の電流は、24V の電源 → THD-R-C → 150Ω の抵抗 → 電源の －（GND）と、ひと回りして流れる
  • GP40T は、ラズパイ → CPI-RAS → GP40T の順に重ねた一番上の基板。ラズパイとは電気的に分けた（絶縁した）電源で動く（GPIO27 で電源を入れる）

150Ω の抵抗を入れている理由

電流の通り道：24V（＋）→ THD-R-C → 出力 A → GP40T の A0 → 150Ω → GP40T の G0 → 24V（－） GP40T は 150Ω の両端（A0 と G0 のあいだ）の電圧を測る。湿度（B → A1 → 150Ω → G1）も同じ形
  • THD-R-C は温度・湿度を電流（4〜20mA）で出すが、GP40T が測れるのは電圧だけ。そこで抵抗に電流を流し、抵抗の両端に出る電圧を測る
  • 電圧 = 電流 × 抵抗：4mA × 150Ω = 0.6V、12mA × 150Ω = 1.8V、20mA × 150Ω = 3.0V
  • 150Ω にしているのは、いちばん大きい 20mA でも 3.0V で、GP40T の 0〜5V の範囲に余裕をもって収まるため
  • 温度用と湿度用で1本ずつ、合わせて2本。A0–G0 のあいだと A1–G1 のあいだに入れる
  • 抵抗で使われる電力は最大でも 20mA × 3.0V = 0.06W と小さく、ふつうの 1/4W の抵抗で足りる（熱くならない）
  • 抵抗の値がずれると、そのまま測った値がずれる（例：抵抗が 1% 大きいと、電流も 1% 大きく計算される）。精度のよい抵抗を使うほど正確になる

数字の計算

電圧[V] = GP40T の数字 × 1.25mV 電流[mA] = 電圧[V] ÷ 150Ω × 1000 温度[℃] = -19.9 + (電流 − 4) ÷ 16 × 79.9 （4mA = -19.9℃、20mA = 60.0℃） 湿度[%] = (電流 − 4) ÷ 16 × 99.9 （4mA = 0%、20mA = 99.9%）
  • 例：温度側が 1.32V → 8.8mA → -19.9 + 4.8 ÷ 16 × 79.9 = 4.1℃
  • 3.6〜20.5mA を外れたら、断線・故障の疑いとして記録しない
  • GP40T は 0〜5V のレンジで使う（実際は 0〜5.12V まで測れる）

加速度センサー記録・表示

加速度センサーX・Y・Z の傾き・揺れを電圧で出す0g = 1.65V、1g で 0.66V 変わる
MCP3004電圧を 0〜1023 の数字に変える（Ch0 = X、Ch1 = Y、Ch2 = Z）基準 3.3V
SPI1ラズパイの2つ目の SPI で読む（GP40T の SPI0 とは別の線）0.1秒ごと
ラズパイ数字 → 電圧 → g に計算して記録今の値は1秒・記録は1分ごと

つなぎ方（ラズパイにつなぐのは4本）

線MCP3004 の足ラズパイのピン基板の「39」の印を上にして見たとき
緑CLK（時計の合図）40番（SPI1 SCLK）上から1番目・ふち側の列
オレンジDIN（ラズパイ → MCP3004）38番（SPI1 MOSI）上から2番目・ふち側の列
黄DOUT（MCP3004 → ラズパイ）35番（SPI1 MISO）上から3番目・内側の列
茶CS（呼び出しの合図）11番（GPIO17。プログラムで Low・High にする）下から6番目（1・2番の側から6段目）・内側の列
  • MCP3004 と加速度センサーの 3.3V・GND は、SHT31 と同じブレッドボードの ＋・－ の列からもらう
  • GP40T（THD-R-C）が使う SPI0 とは別の線（SPI1）なので、THD-R-C の記録と同時に使える
  • CS は SPI1 の決まったピン（12番）ではなく 11番を使い、読むたびにプログラムが Low（呼び出す）・High（終わり）にする。12番では MCP3004 に合図が届かなかったため
  • 読む速さは 100kHz（ゆっくり）で、ch ごとに2回読んで2回目を使う。加速度センサーの出力は電気が弱く、1MHz で読むと正しい電圧になる前に読んでしまい、平らに置いても X・Y・Z がばらばらの値になっていたため
  • 準備として /boot/firmware/config.txt に dtoverlay=spi1-1cs を書く（再起動なしで使うときは sudo dtoverlay spi1-1cs）

数字の計算

G は重力加速度（1G = 地球の重力の強さ、約9.8m/s²）。重さのグラム（g）ではない。

電圧[V] = MCP3004 の数字 ÷ 1023 × 3.3V 加速度[g] = (電圧 − 1.65V) ÷ 0.66V 揺れ[g] = |√(X² + Y² + Z²) − 1| （止まっていれば 0 に近い。1分間・10分間で一番大きかった値を残す）
  • 平らに置くと Z が約 1g（地球の重力）、X・Y が約 0g
  • 換算は、3.3V で使うアナログの加速度センサー（KXR94-2050 など）の値
  • 記録（CSV）：1分ごとに X・Y・Z の平均と、その1分の揺れの最大。templog/accel/日付.csv
  • サイト：湿度のグラフの下に「加速度」の欄が出る（加速度センサーを動かしているときだけ）。右上に今の値（5秒ごと）、グラフは10分ごとの平均と揺れの最大
  • 今の値の揺れは「直近5秒間の最大」。サイトは5秒ごとに読むので、そのあいだに起きた短い揺れ（たたいた、など）も見逃さない

基準（今置いている位置を「正しい位置」にする）

# 基準を決める（5秒間はかって平均する。そのあいだはさわらない）
python3 ~/temp-monitor/accel_base.py

# 基準をやめる
python3 ~/temp-monitor/accel_base.py --clear
  • 今の置き方での X・Y・Z を ~/.config/temp-monitor/accel_base.json に保存する。記録のプログラムは1分ごとに読み直すので、再起動はいらない
  • 基準を決めると、サイトの X・Y・Z は「基準からの変化」になり、「傾き」（基準の向きから何度傾いたか）も出る。置いたままなら、どれも 0 に近い
  • 傾き[度] = 基準の向きと今の向き（X・Y・Z の矢印）のあいだの角度。記録（CSV）には「傾き(度)」の列として残る。X・Y・Z は測ったままの値を残す
  • 止めて置いた状態で、加速度の大きさが 1g から大きく外れているとき（配線の問題などで読めていないとき）は、基準にしない

電源と時計（CPI-RAS）

CPI-RAS は、ラズパイと RPi-GP40T のあいだに重ねる基板。24V の電源からラズパイを動かすことと、 電源が切れても時刻を覚えている時計（RTC）の2つの役目をしている。 これで、THD-R-C と同じ 24V の ACアダプター1つでラズパイも動き、ネットにつながっていなくても正しい時刻で記録できる。

動作確認

sudo i2cdetect -y 1

# 「GPIO busy」の原因を調べる（GPIO を使っているプログラムの一覧）
gpioinfo | grep consumer
ps aux | grep -v grep | grep python

# 動いている記録サービスと、THD-R-C の最新の記録を確認
systemctl list-units | grep -i -E "thd|sht|monitor"

  • I2C で CPI-RAS の 2c と 32（時計）が見えた
  • RPi-GP40T のサンプル（sampleGp40_RPi5.py）が「GPIO busy」になったのは、記録サービス（thdrc-logger）がすでに GP40T を使っていたため。 THD-R-C は正常に記録できていた（故障ではない）

CPI-RAS の時計を使えるようにする

ラズパイ5 本体の時計（rtc0）は、電池をつけていないと電源を抜いたときに止まる。そこで CPI-RAS の時計（rtc1）を使う。 CPI-RAS の時計は RX8900 という部品で、ラズパイに入っている rtc-rv8803 のドライバーで動く。

# 時計のドライバーがラズパイに入っているか確認
modinfo rtc-rv8803 | head -3

# 時計を登録する（I2C の 32 番の部品を RX8900 として登録）
sudo modprobe rtc-rv8803
echo rx8900 0x32 | sudo tee /sys/bus/i2c/devices/i2c-1/new_device
cat /sys/class/rtc/rtc*/name     # rtc0 = ラズパイ5 本体、rtc1 = CPI-RAS

# ネットで時刻が合っているか確認（synchronized: yes なら OK）
timedatectl

# hwclock コマンドを入れる
sudo apt install -y util-linux-extra

# CPI-RAS の時計に今の時刻を書き込み、読み出して確認
sudo hwclock -w -f /dev/rtc1
sudo hwclock -r -f /dev/rtc1

時計のしくみ

1. 時計はずっと動いている

  • CPI-RAS の時計は、ボタン電池（CR2032）で動いている
  • ラズパイの電源が切れていても、コンセントが抜けていても、時刻を刻み続ける

2. 電源を入れたときの時刻

電源を入れた直後の時刻記録への影響
設定する前「最後に電源が切れたときの時刻」から動き始めていた ネットで時刻が合うまでの記録は、ずれた時刻になっていた（今朝の「09:10」がそれ）。ネットがない場所なら、ずっとずれたままだった
設定したあと記録のプログラムが動き出す前に、CPI-RAS の時計から正しい時刻を読み込む 1件目の記録から正しい時刻になる。ネットがない場所でも同じ

補足

  • ずれの修正：ネットにつながっているあいだは、1時間ごとに CPI-RAS の時計も正しい時刻に合わせ直す。 ネットがない場所でも、CPI-RAS の時計は温度の補正が付いているので、ずれは小さく済む
  • ボタン電池の交換：マニュアルでは、電池交換は「修理扱い（販売店か CONTEC に依頼）」となっている。自分で交換しない

時計の電圧・電流

場所大きさメモ
ボタン電池（CR2032）3Vリチウム電池。容量は 約220mAh（CR2032 の一般的な値）
時計の部品（RX8900）が使う電流約0.7µA時刻を刻むだけのときの代表値（部品のデータシートの値。1µA = 0.001mA）
ラズパイとのやり取り（I2C）3.3Vラズパイの 3番・5番ピン（SDA・SCL）。SHT31 と同じ線に、32番として並んでいる
  • ラズパイが動いているあいだは基板の電源で動き、電源が切れると電池に切り替わる（電池で時計を動かす一般的なしくみ。くわしい回路はマニュアルで確認）
  • 電池の持ち：220mAh ÷ 0.0007mA ≒ 31万時間（計算上は何十年分）。実際は電池が自然に減る分などで短くなるので、交換の目安はマニュアルで確認する
  • 時計が使う電気はとても小さいので、24V の電源や、ほかのセンサーの電気にはほとんど影響しない

自動で動くようにする

電源を入れるラズパイの時刻は、前に止まったときのまま（ずれている）
cpi-rtc-loadCPI-RAS の時計を登録し、その時刻をラズパイに読み込む起動時に1回
記録が始まる1行目から正しい時刻で記録される
cpi-rtc-saveネットで時刻が合っていれば、その時刻を CPI-RAS の時計に書き込む1時間ごと
  • CPI-RAS の時計を、ネットで合わせた時刻で1時間ごとに直すので、時計のずれがたまらない
  • ネットで時刻が合っていないとき（ネットなしで起動したときなど）は書き込まない。ずれた時刻で CPI-RAS の時計を上書きしないため
  • 時計の登録は電源を入れるたびに消えるので、起動のたびに cpi-rtc-load で登録し直している

① 起動時に CPI-RAS の時計から時刻を読み込むプログラム（/usr/local/sbin/cpi-rtc-load.sh）

時計のドライバーを読み込み → 時計を登録（まだなら）→ 時計が見えるまで最大10秒待つ → その時刻をラズパイに読み込む

#!/bin/bash
modprobe rtc-rv8803
[ -e /sys/bus/i2c/devices/1-0032 ] || echo rx8900 0x32 > /sys/bus/i2c/devices/i2c-1/new_device
for i in $(seq 1 20); do
  F=$(grep -l rv8803 /sys/class/rtc/rtc*/name 2>/dev/null | head -1)
  [ -n "$F" ] && break
  sleep 0.5
done
[ -n "$F" ] && hwclock -s -f /dev/$(basename $(dirname $F))

② ネットで合わせた時刻を CPI-RAS の時計に書き込むプログラム（/usr/local/sbin/cpi-rtc-save.sh）

ネットで時刻が合っているときだけ → CPI-RAS の時計を探して → 今の時刻を書き込む

#!/bin/bash
[ "$(timedatectl show -p NTPSynchronized --value)" = "yes" ] || exit 0
F=$(grep -l rv8803 /sys/class/rtc/rtc*/name 2>/dev/null | head -1)
[ -n "$F" ] && hwclock -w -f /dev/$(basename $(dirname $F))

③ 起動時に①を動かす設定（/etc/systemd/system/cpi-rtc-load.service）

ネットでの時刻合わせ（time-sync）や、記録のプログラムより前に動かす

[Unit]
Description=Load time from CPI-RAS RTC
DefaultDependencies=no
After=systemd-modules-load.service local-fs.target
Before=time-sync.target sysinit.target

[Service]
Type=oneshot
ExecStart=/usr/local/sbin/cpi-rtc-load.sh
RemainAfterExit=yes

[Install]
WantedBy=sysinit.target

④ 1時間ごとに②を動かす設定（/etc/systemd/system/cpi-rtc-save.service と cpi-rtc-save.timer）

[Unit]
Description=Save system time to CPI-RAS RTC

[Service]
Type=oneshot
ExecStart=/usr/local/sbin/cpi-rtc-save.sh
[Unit]
Description=Save time to CPI-RAS RTC hourly

[Timer]
OnBootSec=5min
OnUnitActiveSec=1h

[Install]
WantedBy=timers.target

⑤ 有効にする

sudo chmod +x /usr/local/sbin/cpi-rtc-load.sh /usr/local/sbin/cpi-rtc-save.sh
sudo systemctl daemon-reload
sudo systemctl enable cpi-rtc-load.service cpi-rtc-save.timer
sudo systemctl start cpi-rtc-save.timer
systemctl list-timers | grep cpi

  • 24V の電源だけでラズパイを動かせる（USB-C の電源はいらない）

露点温度の出し方

露点温度は、空気がそのまま冷えていったとき、何℃で結露しはじめるかの温度。 センサーで直接測っているのではなく、温度と湿度から計算している。 サイトでは「センサーの比較（今の値）」の表と、上のグラフの「露点温度」ボタンで見られる。

今の値（センサーの比較の表）

センサー温度と湿度を測るSHT31・THD-R-C
ラズパイ今の温度・湿度を /api/now で渡す（露点温度は計算しない）5秒ごと
ブラウザサイトの画面の中で、温度と湿度から露点温度を計算5秒ごと
比較の表「湿度」の右の「露点温度」の列に出す小数1桁

計算のしかた（マグヌスの式）

同じ式を、ラズパイ（記録・グラフ用。alarm_settings.py の dew_point）と、サイトの画面（今の値の表用）の両方で使っている。

T = 温度[℃]、RH = 湿度[%] γ = ln(RH ÷ 100) + 17.62 × T ÷ (243.12 + T) 露点温度[℃] = 243.12 × γ ÷ (17.62 − γ)
  • ln は自然対数（電卓の「ln」ボタン）。17.62 と 243.12 は、水の上の空気で使う決まった数（-45〜60℃ で使える）
  • 例：温度 23.3℃・湿度 46.3% のとき
    • γ = ln(0.463) + 17.62 × 23.3 ÷ 266.42 = -0.770 + 1.541 = 0.771
    • 露点温度 = 243.12 × 0.771 ÷ (17.62 − 0.771) ≒ 11.1℃
    • つまり、この空気が 11.1℃ まで冷えると結露しはじめる
  • 計算の誤差は ±0.1℃ くらい。それよりも、センサーの湿度の誤差のほうが大きく効く（室温くらいなら、湿度が 3% ずれると露点温度は 0.7〜1.4℃ くらいずれる）

どのセンサーで出しているか

  • SHT31：自分の温度と湿度から計算
  • THD-R-C：自分の温度と湿度から計算。下に小さく「SHT31 との差」も出す
  • Pt100・K型熱電対：湿度を測っていないので「--」（ほかのセンサーの湿度を借りて計算することはしていない）

見方の目安

  • 壁・窓・製品など、ものの表面の温度が露点温度より低いと、そこに結露する
  • 温度と露点温度の差が小さいほど（湿度が高いほど）、結露しやすい
